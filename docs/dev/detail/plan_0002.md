# plan_0002 - 시나리오 생성 결과의 서사/상태 정합성 회귀 테스트 베이스 구축

## User Requirements

- 테스터 중심으로 서사적/상태적 불일치를 탐지하고 수정 가능한 기반이 필요함.
- 상태관리 서비스(state-manager)와 연동된 실검증 경로가 필요함.

## Goal

- 시나리오 생성 결과를 state-manager 주입까지 포함해 검증하는 테스트 베이스를 표준화한다.
- 생성된 서사(시퀀스 흐름)와 상태 데이터(엔티티/관계/배치)의 불일치를 자동 탐지한다.

## Scope

- In:
  - `scripts/test_generation_integration.py` 검증 항목 확장
  - 생성 결과 스냅샷 저장(`fixtures` 또는 `artifacts`) 및 비교 루틴
  - state-manager 주입 응답 계약 검증
- Out:
  - 신규 생성 알고리즘 도입

## Implementation Plan

- Step 1: 생성 직후 payload와 주입 직후 payload를 각각 저장하고 diff 계산.
- Step 2: 필수 정합성 규칙(액트-시퀀스 참조, 엔티티 참조, relation endpoint 유효성) 추가.
- Step 3: 실패 케이스를 `NarrativeStructureMismatch` / `StateReferenceMismatch`로 분류.
- Step 4: 회귀 테스트에서 동일 컨셉 입력 시 핵심 구조가 유지되는지 계약 검증.

## Unit Test Plan (must)

- What to test:
  - 패키징 로직의 참조 무결성
  - 스키마 보정 로직(필드명 변동) 안정성
- Command:
  - `uv run pytest tests/test_engine.py tests/test_infra_db_mapping.py`

## E2E Plan (must)

- How to run:
  - `uv run python scripts/test_generation_integration.py --real --host <gateway-host>`
- Validation:
  - 주입 성공 + 불일치 카테고리 0건.
  - 실패 시 구조 diff와 참조 경로를 즉시 출력.

## Done Criteria

- [ ] 생성-주입 통합 검증 경로 안정화
- [ ] 서사/상태 불일치 자동 분류 도입
- [ ] 회귀 테스트 베이스(아티팩트 기반) 마련
- [ ] docs/dev 문서 갱신
